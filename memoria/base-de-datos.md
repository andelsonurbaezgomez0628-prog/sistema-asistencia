# Modelo de datos (resumen de trabajo)

Motor PostgreSQL en Neon. El detalle esta en [`../docs/base-de-datos.md`](../docs/base-de-datos.md);
la URI solo vive en `.env`.

## Relaciones

```text
usuarios 1:N secciones N:1 cursos
secciones 1:N estudiantes
estudiantes 1:N asistencia (UNIQUE estudiante_id + fecha)
estudiantes 1:N alertas
sesiones: persistencia de acceso separada
```

## Consultas frecuentes

```sql
SELECT COUNT(*) FILTER (WHERE estado = 'ausente') AS faltas,
       COUNT(*) FILTER (WHERE estado = 'tardanza') AS tardanzas
FROM asistencia
WHERE estudiante_id = $1 AND fecha BETWEEN $2::date - 29 AND $3::date;
```

```sql
INSERT INTO asistencia (estudiante_id, fecha, estado, observacion, creado_por)
VALUES ($1, $2, $3, $4, $5)
ON CONFLICT (estudiante_id, fecha)
DO UPDATE SET estado = EXCLUDED.estado, observacion = EXCLUDED.observacion;
```

Identidades con `GENERATED BY DEFAULT AS IDENTITY`, estado activo `BOOLEAN`, y checks para roles
y enums. El seed inserta algunos IDs fijos y reajusta sus secuencias con `setval`.

## Reglas a preservar

- `justificado` no suma al riesgo; `tardanza` cuenta como asistencia.
- 3 faltas no justificadas en 30 dias: medio; 5 o racha de 3 dias: alto.
- Desactivar, no eliminar, estudiantes/docentes con historial.
- La fecha de negocio es `CURRENT_DATE` de PostgreSQL.
- La demo debe producir 3 cursos, 4 secciones, 20 estudiantes y 4 alertas pendientes.
